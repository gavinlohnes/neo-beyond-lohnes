## Fixture provenance and exercised operation

In an isolated developer browser, existing application commands created one active day, manual
OFF context, a GREEN check-in, one open Capture note, one open Journal decision, one active Mission
and one linked Obligation. The notes explicitly identify synthetic demonstration content. MORE's
real EXPORT BACKUP produced the fixture. Each fresh production browser imported that file through
the real native picker, validated preview and CONFIRM REPLACE, including automatic safety backup.
No direct IndexedDB manipulation or production fixture/schema change was used.

At every width: verified exactly two starts, original index access, guided Journal/task input,
in-memory draft retention across BACK TO MORE/return, user-selected Small Steps, Capture draft
retention across Minimum Day inspection/all-tools, actual BODY +8oz → UNDO → 0oz, and primary-tab
return. After service-worker activation, disabled network and cold-reloaded: MORE read context,
an explicitly saved task appeared in the original list and changed the canonical count from one
to two; Capture explicitly saved an offline note. No horizontal overflow at these capture states.

## Truth and limitations

Starts have fixed reflection/direction slots. Canonical counts choose destination copy, not urgency,
due-date rankings, personal inference or Engine recommendations. No clock-based daily rotation.
The list reads on MORE entry/return, visible resume and explicit retry; supporting explanation is
under WHY THESE STARTS. Pending/failed reads replace contextual counts with labelled generic starts.
Archived or invalid-parent Mission obligations cannot supply current-eligible counts.

Journal remains a decision record requiring an actual decision; plain memories stay in Capture.
Prompts do not prefill, save, assign dates or change plans. Fixed-description omission on named
MORE rows remains; the optional destination guide explains existing capabilities separately.

Small Steps is chosen from the existing TOOLS toolbar; closed-TOOLS TODAY keeps its previous layout.
It is session-local UI, not a new capacity assessment or persisted plan. Minimum Day's
thresholds, six items, explicit enable, Engine guidance, active operation priority, schedule, manual
controls and undo are unchanged. The selected tool's companions stay mounted but hidden until
SHOW ALL TOOLS, returning to Small Steps or ordinary TOOLS/SYSTEM navigation. Essentials are not
hidden. Original water returns via the TODAY tab; meals retain their existing dedicated return.
The untouched meal round-trip suite and an additional Small Steps round-trip regression preserve
the original draft, focus and position contract. Exiting Small Steps opens all tools and restores
focus to the opt-in control.

MORE creation drafts survive internal inspection/return, not reload or ordinary primary-tab
navigation. The new guided Capture shortcut explicitly asks before discarding an unfinished MORE
creation draft; cancelling preserves it. No new draft persistence or cross-tab storage is claimed.
Existing write semantics/commands and their integrity limitations are unchanged. Capture failures
retain text; known successful saves followed by a read failure do not invite duplicate saves.

Not tested on physical phones, Safari/iOS, native assistive technology, native share-sheet/file
provider behavior, arbitrary-large histories or cross-tab concurrency. Existing production bundle
warning remains. Independent exact-head review, green required CI and Gavin's separate merge
decision are required; no merge/deployment is authorized by this evidence.
