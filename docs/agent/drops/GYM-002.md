# GYM-002 // CUE TEXT PER LIFT

## Mission

Gavin's own short cue text per lift ("Squat: brace, knees out, slow down"), written once and
shown in the gym screen. Owner ruling 2026-10-04, decision 2A: stored in BEYOND's database so it
is included in backups and survives a phone change.

## Approved baseline

Set to a fresh `origin/master` SHA after GYM-001 merges (the builder updates `baseline:` before
`factory-drop.mjs init`).

## Risk classification

HIGH-RISK: new stored data. Boundary crossed: schema/migration and the backup contract (the new
data must round-trip through backup and restore). The owner's storage ruling is obtained (2A);
the builder still stops at the plan and gets Gavin's sign-off on the exact storage change before
writing it.

## Authorized scope

- Storage: the smallest additive option, chosen in the plan for Gavin's sign-off: an event
  (`EXERCISE_CUE_SET`) in the existing events table, which needs no schema version change, or a
  new Dexie table `exerciseCues` in a new additive `db.version`. Prefer the event if it meets
  the need.
- An edit control in the gym screen (and on custom exercises in MORE → Exercise Library): up to
  140 characters, plain text.
- A backup/restore round-trip test with a cue present; protected-fixture restores still pass.

## Explicit exclusions

No cue sharing, rich text or cue suggestions; no change to an existing table's shape.

## Relevant authority / references

`.claude/rules/persistence.md` (migrations additive-only; backup format changes are High-Risk);
`docs/UX_DECISIONS.md` "Gym mode (owner rulings 2026-10-04)".

## Required invariants

Older backups (including protected fixtures) restore unchanged; a backup with cues restores them.

## Acceptance criteria

1. A cue saved for a lift shows in the gym screen for that lift and survives a reload.
2. Backup then restore keeps the cue.
3. Protected-fixture and legacy restore tests pass unchanged.

## Required verification

`npm run verify` · `npx vitest run tests/compat/` · the backup/restore round-trip test ·
`npm run check:risk -- <baseline>` · PR Verification green.

## Builder expectations

Stop after the plan for Gavin's sign-off on the exact storage change; then build, verify, PR.

## Reviewer expectations

Independent review of migration/back-compatibility and the round trip.

## Integrator expectations

High-Risk: Gavin approves the merge.

## Stop / escalation conditions

Stop on any change to an existing table's shape or to how existing backups parse.
